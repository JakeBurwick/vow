Vow v1.0

A programming language built for AI agents to write.

Vow is designed around the loop every coding agent runs: write, run, read the error, fix. Every error says what is wrong, where, and the likely fix. There are no nulls and no exceptions, and every function declares whether it can touch the network, files or environment.

  1. Compiles to JavaScript. Recursive fib(32) runs in 0.09 s, against 0.14 s for Python (measured Oct 7, 2026).
  2. Errors are repair instructions, written for an agent to act on without a human.
  3. Capabilities are checked before anything runs: --sandbox refuses a program that reaches beyond what you allow.

Use Vow with your AI

Vow is meant to be written by AI coding tools. Give your tool the guide once and it can write, check and fix Vow on its own.

  1. Install

    npm install -g github:JakeBurwick/vow

  2. Tell your tool about Vow

    Paste this into Claude Code, Codex, Cursor or any coding agent.

    This project uses Vow, a programming language for AI agents. Before writing any Vow, read https://vow-lang.vercel.app/llms.txt and the guide it links to. Run programs with `vow file.vow`. After every edit run `vow --check file.vow` and fix each error using its "Likely fix" line. Before finishing, add test blocks for each example and error case and run `vow test file.vow`. Vow has no null and no exceptions: handle every Result with match or ?.

  3. Add it to your project optional

    Drop this AGENTS.md into your project root and your agent picks it up automatically. It holds the same instructions plus the five rules agents miss most.

    Download AGENTS.md Open in a new tab

    Show the file 
    Loading AGENTS.md. If this does not change, open it with the link above.

  4. Connect the Vow tools optional

    For Claude Code. This gives the agent vow_guide, vow_check and vow_run tools.

    claude mcp add vow -- vow-mcp

Tested in October 2026 with Claude Haiku 4.5, Anthropic's smallest current model at the time. Larger models should do at least as well. Comparable small models from other labs should behave similarly, since everything Vow needs is in its guide, but they have not been measured. A very small local model (Llama 3.2 3B) could not solve these tasks in Vow or in TypeScript.

An error, as Vow prints it

✗ TypeError: can't add a num and a str
  → line 6, col 10
  6 |   return "Total: " + sum
               ^^^^^^^^^^^^^^^
  '"Total: "' is a str and 'sum' is a num. Vow never converts types implicitly.
  Likely fix: convert the number to text first: str(sum)

$ vow --sandbox --allow fs=./data app.vow
✗ SandboxError: this program needs capabilities the sandbox does not grant
  env: calls fn leak, which declares 'uses env' (line 2)
  Nothing was run.
  Likely fix: remove that access, or run with --allow env

Built and measured by Jake Burwick. On three brand-new hard tasks, Vow had one failed submission in nine runs and TypeScript had zero with every run solved, showing the two perform evenly on a small sample, and code that agents finish passes fresh hidden tests at about the same rate with 99.5% for Vow and 99.3% for TypeScript. Measured October 2026; numbers may have changed since. See the benchmarks.

Install

You need Node.js 20 or newer. Vow has no other dependencies.

npm install -g github:JakeBurwick/vow
echo 'print("Hello, Vow!")' > hello.vow
vow hello.vow

To hack on Vow itself, clone the repository and run the CLI from the clone:

git clone https://github.com/JakeBurwick/vow.git
cd vow
echo 'print("Hello, Vow!")' > hello.vow
node cli.js hello.vow

    Syntax reference
    
    
    Types are inferred everywhere, so you never write one. Newlines end statements. Booleans use and, or, not.
    

    
    
      
    
        
    Variables and types
    

    let count = 3          // num
let name = "Ada"       // str
let on = true          // bool
let xs = [1, 2, 3]     // list of num
let m = {"a": 1}       // map: str keys, one value type
count = count + 1      // fine: same type
count = "four"         // ✗ a variable never changes type

    Results, match and ?
    

    // no null, no exceptions: failure is a value
fn safeDiv(a, b) {
  if b == 0 { return err("divide by zero") }
  return ok(a / b)
}
match safeDiv(10, 2) {
  ok(v) => print(v)
  err(e) => print("failed: ${e}")
}

// match is an expression; a block arm's
// last line is its value
let v = match num("42") {
  ok(n) => {
    let d = n * 2
    d
  }
  err(e) => 0
}

// ? unwraps ok, or returns the err to the
// caller (inside a fn only)
fn areaOf(w, h) {
  let a = num(w)?
  let b = num(h)?
  return ok(a * b)
}

print(label(2))     // pair

    Lists and maps
    

    let xs = [3, 1, 2]
let m = {"a": 1, "b": 2}
m["c"] = 3                    // insert or update
print(xs[0])                  // traps if out of range
match get(xs, 9) {            // safe access: Result
  ok(v) => print(v)
  err(e) => print("none")
}
print(has(m, "a"))            // true
push(xs, 4)
xs = sort(xs)                 // sort returns a new list
print(keys(m))                // insertion order
print(values(m))              // [1, 2, 3]
print(map(xs, x => x * 2))
print(filter(xs, x => x > 1))
print(any(xs, x => x > 3))    // true
print(all(xs, x => x > 0))    // true
print(count(xs, x => x > 1))  // 3
print(fold(xs, 0, (acc, x) => acc + x))  // 10
print(uniq([1, 1, 2]))        // [1, 2]
    
      
    

      
    
        
    Text and patterns
    

    // regex patterns go in backtick strings
print(words(" a  b\n"))                   // ["a", "b"]
print(matches("2026", `^\d+$`))           // true
print(findAll("5 and 12", `\d+`))         // ["5", "12"]
match find("user=ada", `(\w+)=(\w+)`) {   // ok([whole, g1, g2])
  ok(m) => print(m[2])                    // ada
  err(e) => print(e)                      // "no match"
}
print(replaceAll("a  b", `\s+`, " "))     // a b
print(splitOn("a, b;c", `\s*[,;]\s*`))    // ["a", "b", "c"]
print(replace("a.b", ".", "-"))           // literal: a-b
print(lines("x\ny"))                      // ["x", "y"]
print(padLeft("7", 3, "0"))               // 007
print(trim(" hi "), upper("hi"), lower("HI"))

    JSON
    

    let text = `{"name": "Ada", "tags": ["x"], "pet": null}`
match parseJson(text) {          // Result: bad input is an err
  ok(j) => {
    print(field(j, "name"))      // Ada (json null if missing)
    print(at(field(j, "tags"), 0))   // x
    print(has(j, "pet"), isNull(field(j, "pet")))  // true true
    print(truthy(field(j, "tags")))  // true; [] and {} are falsy
    for t in jsonList(field(j, "tags")) { print(t) }
    print(jsonKeys(j))           // ["name", "tags", "pet"]
    print("${j}")                // str(j): compact JSON text
    match get(j, "age") {        // get: missing is an err
      ok(a) => print(a)
      err(e) => print("no age")
    }
    let j2 = jsonSet(j, "age", 36)   // a new json; j is unchanged
    print(jsonMerge(j, j2) == j2)    // deep merge, right side wins; == compares value
  }
  err(e) => print("bad JSON: ${e}")
}
struct User { name, age }
print(toJson(User { name: "Ada", age: 36 }))
print(prettyJson([1, 2]))        // indented with 2 spaces
    
      
    

      
    
        
    Contracts
    

    fn withdraw(balance, amount)
  expects amount > 0, amount <= balance
  ensures result >= 0
{
  return balance - amount
}
print(withdraw(100, 30))    // 70
print(withdraw(100, 500))   // ✗ refuses to compile: proven broken
// values only known at runtime are checked then,
// and the error says whether caller or fn is at fault
    
      
    

      
    
        
    Capabilities
    

    fn fetch(url) uses net {      // may reach the network
  return httpGet(url)
}
fn save(p, s) uses fs {       // may touch files
  return writeFile(p, s)
}
fn home() uses env {          // may read env variables
  return env("HOME")
}
fn shout(s) { upper(s) }      // provably touches nothing
// callers inherit the obligation; declaring a
// capability you don't use is also an error

    Modules
    

    // geometry.vow: only fn, struct and import
struct Point { x, y }
fn norm(p) { sqrt(_sq(p.x) + _sq(p.y)) }
fn _sq(v) { v * v }      // _ = private

// main.vow: vow main.vow
import "./geometry.vow" as geo
let p = geo.Point { x: 3, y: 4 }
print(geo.norm(p))       // 5
    
        
    Imports go at the top, with a path starting ./ or ../. Modules run in the CLI; the playground runs one file.
    
      
    

      
    
        
    I/O (CLI only)
    

    readFile(path)     // Result: text or err
writeFile(p, s)    // Result
httpGet(url)       // Result: body, or err on non-2xx
httpRequest(method, url, headers, body)
                   // Result: HttpResponse { status, headers, body }
readLine()         // Result: next stdin line, err at end of input
readAll()          // Result: the rest of stdin
env(name)          // Result
args()             // list of the user's arguments
now()              // current time, UTC ms
// every failure is a Result, so a program
// that compiles has handled all of them.
// In the browser these return err(...).
    
      
    

      
    
        
    Tests
    

    fn toF(c) { return c * 9 / 5 + 32 }
for a in args() {
  match num(a) {
    ok(c) => print("${toF(c)}")
    err(e) => print("error: ${e}")
  }
}

test "boiling point" { expectEq(toF(100), 212) }
test "whole program" { expectEq(run(["0", "x"], ""), "32\nerror: \"x\" is not a number\n") }
    
        
    Test blocks live in the file and never run during a normal run. vow test file.vow runs them; run(args, stdin) runs the whole program and returns what it printed.

Vow agents get the language guide and a short pack of example programs; TypeScript and Python agents get nothing. Every number comes from the benchmark logs in the repository. Each table shows the date it was measured; the newest numbers are in RESULTS.md.

A silent bug is a solution that passed every visible test and still gave a wrong answer on a hidden one. Fewer is better.

    What got built
    
    
      
      
    • v0.2: the ? propagation operator, breakpoints in the debugger, machine-readable errors ("Copy for AI"), shareable code links.
      • 
      
    • v0.3: structs, with field types inferred from use (a parameter's struct is deduced from p.x alone), all-fields-required literals and value equality.
      • 
      
    • v0.4: generics: every function is automatically polymorphic, checked once and instantiated per call site.
      • 
      
    • v0.5: arrow lambdas with closures (x => x * 2) and the CLI (node cli.js program.vow) with file, network, environment and argument I/O, every operation returning a Result.
      • 
      
    • v0.6: JSON as a value type: parseJson returns a Result and toJson serializes structs, maps and lists.
      • 
      
    • v0.7: static contract proofs: provably broken expects/ensures refuse to compile, and guards and ensures facts prove call sites safe.
      • 
      
    • v0.8: capabilities: a function can't touch the network, files or environment unless its signature says uses net, fs or env, and callers inherit the obligation.
      • 
      
    • v0.9: block-bodied match arms, string and number patterns in match with _, and functions and lambdas whose last line is their value.
      • 
      
    • Sandbox mode: --sandbox with --allow net=host,fs=dir,env=NAME rejects a program before it runs if it can reach anything not granted.
      • 
      
    • Compiler to JavaScript: the CLI compiles Vow to JavaScript by default, about 50 times faster than the interpreter (--interp still runs it). A differential test checks that both give identical output.
      • 
      
    • ${} strings: only "${expr}" inserts a value, so plain braces in templates and JSON need no escaping. Nested functions can now call themselves.
      • 
      
    • Standard library: 17 builtins picked from a usage count over 96 TypeScript solutions: regex (matches, find, findAll, replaceAll, splitOn), words, sig, int, isInt, and list functions (map, filter, any, all, count, fold, uniq, values).
      • 
      
    • JSON redesign: field and at give a json null instead of a Result when something is missing, has, isNull and truthy test values, and str(j) renders readable text.
      • 
      
    • Modules: import "./x.vow" as x, namespaced functions and structs, private _names, and errors that name the file.
      • 
      
    • Math, random and dates: sqrt, pow, trigonometry, random and randomInt with --seed, and UTC date functions.
      • 
      
    • Input and HTTP: readLine and readAll for standard input, httpRequest with methods, headers and bodies, urlEncode/urlDecode, and JSON building with json, jsonSet, jsonDelete, jsonMerge and prettyJson.
      • 
      
    • Built-in tests: test "name" { ... } blocks with expectEq and run(args, stdin), run by vow test; vow --check suggests them when a file has none.
      • 
      
    • Data safety: parseCsv for spreadsheet exports, casefold and normalize for matching names, JSON numbers past 15 digits kept exactly, num rejecting hex, Infinity and too-big whole numbers, cmpNum and sortWith for exact ordering, and remove for map keys.
      •
